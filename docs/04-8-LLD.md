# LLD Module 8 — Streamlit App
## SnowComotive — Predictive Maintenance & Overall Equipment Effectiveness (OEE) Command Center

Status: Draft v0.1
Traces to: [02-FRD.md](02-FRD.md) Section F (FR-CC-01 through 07) | [03-HLD.md](03-HLD.md) §5 | [04-6-LLD.md](04-6-LLD.md)

Page-by-page widget/chart layout. Every widget's data source is a Consumption table (Module 1) or the agent (Module 7) — nothing here queries `FEAST` or Raw/Standardized directly (FR-PL-05's whole point is that Consumption is what downstream consumers read).

---

## 0. App shell

- **Sidebar**: persona switcher (`st.radio` or `st.selectbox`, 3 options — FR-CC-04), machine filter (defaults to all 3 sensor-enabled machines), and the demo-only tick-injection button (§5, admin/demo visibility only — hide behind a query param or secret flag so it's not visible to judges unless intentionally shown).
- **Main area**: 5 pages via `st.navigation`/`st.tabs` — Overview, Priority Queue, Forecast OEE, Agent Chat, Impact Statement (HLD §5). Persona switch changes which pages/actions are enabled, not the page list itself (all 3 personas can view all pages — FR-SA-02 restricts *tools*, not *views*, since read access to OEE/health data is universal, only ticketing differs).

---

## 1. Overview (FR-CC-01)

- **Health status row**: 3 cards (`st.metric` or custom), one per sensor-enabled machine — current `anomaly_score` + status badge (healthy/watch/at-risk, thresholded off `cons.fct_anomaly_result`'s latest row per machine).
- **OEE trend chart**: line chart, `cons.fct_oee`, `availability_pct`/`oee_pct` by `line_name` over `period_week` — weekly, with a monthly-rollup toggle.
- **Sensor detail (expandable per machine)**: raw `reading_value` over time from `cons.fct_sensor_reading`, filtered to the selected machine's 3 sensor types — this is the one place the lean atomic fact (not `FEAST`) is charted directly, since the dashboard wants real physical units, not z-scores.

## 2. Priority Queue (FR-CC-02)

- **Ranked table**: `cons.fct_priority_score`, sorted by `priority_score` descending, columns = machine, priority score, and the 4 contributing factors (`rul_urgency`, `demand_pressure`, `inventory_buffer`, `spare_part_readiness`) so "why this ranking" is inspectable without opening the agent (FRD's explicit requirement).
- **Bar chart**: stacked bar per machine, one segment per contributing factor (weighted by HLD §5's formula coefficients) — visualizes *why* one machine outranks another, not just that it does.
- Row click → jumps to Overview's expandable sensor detail for that machine (lightweight cross-page nav, `st.session_state`).

## 3. Forecast OEE (FR-CC-03)

- **Projected Availability chart**: line chart, one series per line, spanning the 8-week look-ahead — combines `cons.fct_rul_prediction` (translated to calendar-day risk windows per BRD assumption 8) against `cons.fct_order`'s look-ahead volume (A6) to shade weeks where a flagged machine's predicted failure window overlaps a demand peak.
- This is the chart that carries demo beat 7 (BRD §7) — the "Caliper line's projected Availability dip next week" moment. Needs both series' look-ahead data visibly present, not just historical trend.

## 4. Agent Chat (FR-CC-05)

- Persona-scoped chat panel (`st.chat_message`/`st.chat_input`), backed by the Cortex Agent for the currently-selected persona (Module 7) — one Streamlit page, three different agent objects depending on sidebar selection, not three separate pages.
- Tool-call transparency: when the agent calls `create_jira_ticket`/`request_jira_ticket`, surface a visible confirmation in the chat, not just prose — the ticket ID/link either way, but distinctly worded for a new ticket (`CREATED`) vs. a duplicate-check hit (`ALREADY_OPEN`/`RECENTLY_CLOSED`, FR-JR-04) so the presenter doesn't accidentally claim a fresh ticket was filed when the tool actually returned an existing one.

## 5. Impact Statement (FR-CC-07)

- 4 metric cards (`st.metric`), one per BRD §8 metric: unplanned downtime reduction %, time-to-detect improvement, $ at-risk revenue protected, concordance index — computed from actual pipeline/model output (Module 5 §3's evaluation, plus a downtime/impact rollup query), never hardcoded.

## Demo-only control (FR-CC-06)

A single button, "Inject next tick" — calls FR-PL-04b's manual trigger (uploads the next pre-generated Parquet file, fires `COPY INTO`). Placed in the sidebar, not a page of its own, and should visibly disable/spin while the tick propagates so the presenter can narrate the wait without dead air.
